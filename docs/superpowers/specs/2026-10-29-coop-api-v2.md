# Ruffle Together co-op API, round 2 (2026-10-29)

User's ask: "add api stuff for camera, label, etc. discord presence, browser play ... buttons the game defines
itself". Choices: first batch is Claude's pick; browser play runs in its own session; Discord with a placeholder
application id (the user makes the real one); game-defined buttons sit next to `.keys` files.

Saved before starting: `ruffle-stable/2026-10-29-4a3cd49` (tag `stable-2026-10-29-4a3cd49`).

## The rule

Every call is **shared** (same answer or effect on every PC on the same frame) or **local** (only changes the
picture on this PC). Local calls never touch the display tree, so the fingerprint stays honest. Every call is
optional; a game that calls nothing plays exactly as before (the BIC/GM2/TW replays must not change).

## Calls (all through `ExternalInterface.call`, AS2 and AS3)

| Call | Kind | What it does |
|---|---|---|
| `coop.version` | shared | API version number (2) |
| `coop.has(name)` | shared | true if this build has the feature (`"camera"`, `"hud"`, `"label"`, `"keys"`, ...) |
| `coop.name(slot)` | shared | that player's name |
| `coop.isHost` | local | true on the host's PC (like `localSlot`: never for gameplay) |
| `coop.camera(slot, x, y, zoom)` | shared data, local effect | sets that slot's camera: the stage point (x, y) is shown at the centre of the screen at `zoom` (1 = normal). Each PC draws with its own slot's camera. The game calls it for every slot, so every PC holds the same values. `coop.camera(slot)` with no position turns it off |
| `coop.hud(path)` | local effect | the clip at `path` (e.g. `"_root.hud"`, a child of the root) is drawn without the camera |
| `coop.label(slot, path, text)` | local effect | Ruffle draws `text` above the clip at `path` on every PC (a name tag), as an overlay, not a game object. `text` empty removes it |
| `coop.keys(text)` | shared | the game gives its own key map, in the `.keys` format, from that frame on (game-defined buttons). The SWF is the same on every PC (the handshake checks its hash), so every PC switches on the same frame |

The mouse: each PC turns its cursor into stage coordinates through its own camera before sending it, so
`coop.mouseX/Y(slot)` and the host's normal mouse stay in game coordinates on every PC.

## How

- Camera: `Stage` keeps a view matrix that `render_viewport` multiplies after the viewport matrix (screen only;
  `BitmapData.draw` and bitmap caching never see it). The Stepper sets it from the local slot's camera before it
  renders. HUD clips get a `COOP_HUD` display-object flag; `render_base` undoes the camera for them.
- Labels: drawn by the desktop GUI (egui) over the game, at the clip's stage position through camera and viewport.
- `coop.keys`: parsed with the existing `Game::parse`; the Stepper swaps its `GameKeys` (held keys released first).
- Paths: `_root`/`_level0` then instance names, resolved from the root clip (works in AS2 and AS3).

## Also in this round

- `RuffleTogether.as` (AS2 and AS3): `RT.camera(...)` etc., feature checks, the SWF<8 `ASSetPropFlags` step, and a
  plain-Flash fallback (slot 0, no camera).
- Discord Rich Presence (desktop only, local): "Playing <game> - room ABCDE (2/4)". Placeholder app id in one
  constant; off when it's the placeholder or Discord isn't running. Never touches the game.
- Browser play: separate session and branch (Ruffle web build + lockstep + WebSocket relay).

## Tests

- api: every call's answer; bad slots and paths give undefined; `has`/`version`.
- camera: two PCs with different local slots and different cameras give equal fingerprints; the rendered picture
  moves; HUD doesn't move; mouse through the camera round-trips.
- keys: a game's `coop.keys` text switches the map on the same frame on every PC.
- BIC/GM2/TW replays unchanged.

## Not in this round

Split screen, spectators, mid-game join, patch SWFs, hooks, variable-level desync checks (later rounds).
